# Backend API

Этот документ описывает минимальный Flask-бэкенд приложения CrocoMim: доступные маршруты, формат запросов и вспомогательные функции.

## Запуск
Бэкенд запускается из `backend/app.py`. По умолчанию сервер слушает `http://localhost:3000`.

### Отправка отзывов на почту
Для доставки отзывов по email задайте переменные окружения:

- `SMTP_HOST` — адрес SMTP-сервера (обязательно).
- `SMTP_PORT` — порт SMTP (по умолчанию `587`).
- `SMTP_USERNAME` / `SMTP_PASSWORD` — учётные данные для авторизации (опционально).
- `SMTP_STARTTLS` — включить STARTTLS (по умолчанию `true`). Любое значение из `false`, `no`, `0` отключит его.
- `FEEDBACK_RECIPIENT` — адрес получателя писем (обязательно).
- `FEEDBACK_SENDER` — адрес отправителя (по умолчанию `SMTP_USERNAME`, иначе `FEEDBACK_RECIPIENT`).

Отправленное письмо включает категорию, текст сообщения, контактный email (если указан), а также сериализованные поля `context` и `client`.

### Локальный лог
Параллельно отзыв сохраняется построчно в файл. Путь задаётся переменными окружения `DATA_DIR` (каталог) и `FEEDBACK_FILE` (имя файла). При отсутствии каталога он будет создан автоматически.

## Маршруты
### `GET /`
- **Описание:** проверка живости сервера.
- **Параметры:** нет.
- **Ответ:** `{ "message": "Flask backend is alive" }`.

### `GET /healthz`
- **Описание:** health-check.
- **Параметры:** нет.
- **Ответ:** `{ "ok": true }`.

### `GET /version`
- **Описание:** возвращает текущую версию бэкенда.
- **Параметры:** нет.
- **Ответ:** `{ "version": "0.6.0" }` (пример).

### `POST /generate-dictionary`
- **Описание:** генерирует список слов по теме и выбранной сложности через OpenRouter (`backend/services/llm_service.py`).
- **Тип:** `POST`
- **Заголовки:** `Content-Type: application/json`
- **Тело запроса (JSON):**
  - `topic` — **обязательный**, строка длиной от 3 символов.
  - `difficulty` — **обязательный**, одно из поддерживаемых значений (`easy`, `medium`, `hard`).
- **Ответы:**
  - `200 { "ok": true, "topic": "...", "difficulty": "...", "count": 30, "words": ["word1", ...] }` — словарь успешно сгенерирован.
  - `400 { "ok": false, "errors": [...] }` — ошибки валидации (пустая тема, неподдерживаемая сложность).
  - `500 { "ok": false, "error": "..." }` — внешняя модель вернула ошибку.

### `POST /feedback`
- **Описание:** принимает отзыв от клиента, сохраняет его построчно в лог-файл и отправляет на почту.
- **Тип:** `POST`
- **Заголовки:** `Content-Type: application/json`
- **Тело запроса (JSON):**
  - `category` — **обязательный**, одно из `typo`, `difficulty`, `other`.
  - `message` — **обязательный**, строка длиной не менее 10 символов.
  - `email` — опционально, непустая строка.
  - `consent` — **обязательный**, булев `true`.
  - `context` — опционально, объект с произвольными данными (например, режим игры, слово, сложность).
  - `client` — опционально, объект с данными клиента (например, userAgent, platform).
- **Ответы:**
  - `200 { "ok": true }` — отзыв сохранён.
  - `400 { "ok": false, "error" | "errors": [...] }` — некорректное тело или ошибки валидации.
  - `500 { "ok": false, "error": "Failed to persist feedback: ..." }` — не удалось записать данные на диск.
  - `500 { "ok": false, "error": "Failed to deliver feedback (logged locally): ..." }` — письмо не ушло, но запись сохранена в лог.

## Вспомогательные функции
### `backend/app.py`
- `_resolve_storage_path()` — возвращает путь к файлу для сохранения отзывов с учётом `DATA_DIR` и `FEEDBACK_FILE`, создаёт каталог при необходимости.
- `_validate_feedback(payload)` — проверяет входные данные, возвращает объект с полем `ok` и списком ошибок (если есть).
