# Обратная связь в CrocoMim

Документ описывает работу встроенной формы обратной связи и способы интеграции с серверной частью.

## UI и точки запуска

- **Главное меню** — кнопка «Обратная связь» расположена сразу под блоком настроек темы.
- **Быстрый режим** — иконка-флажок рядом с текущим словом.
- **Командный режим** — иконка-флажок рядом с текущим словом.
- Горячая клавиша **F** открывает форму на активном экране (home/quick/team).

Каждый запуск модалки автоматически заполняет контекст: режим (`mode`), идентификатор и текст слова (если есть), сложность, временная метка, версия приложения и язык интерфейса.

## Поведение формы

- Обязательные поля: категория, описание (минимум 10 символов), согласие на обработку данных.
- Дополнительное поле `email` позволяет оставить контакт для ответа.
- После успешной отправки отображается toast «Спасибо! Мы получили вашу обратную связь.»
- Если отправка невозможна (офлайн или ошибка сервера), черновик сохраняется локально и пользователь видит уведомление «Сохранено офлайн, отправим при подключении» плюс кнопку «Отправить через почту».

## Сетевая часть

### Запрос

```
POST /feedback
Content-Type: application/json

{
  "category": "typo" | "difficulty" | "other",
  "message": "string",
  "email": "string | null",
  "consent": true,
  "context": {
    "mode": "quick" | "team" | "home",
    "termId": "string | null",
    "termText": "string | null",
    "difficulty": "easy" | "medium" | "hard" | "mix" | null,
    "timestamp": "ISO8601",
    "appVersion": "string",
    "language": "string"
  },
  "client": {
    "userAgent": "string",
    "platform": "string"
  }
}
```

Ожидается ответ `200 OK` с телом `{ "ok": true }`. Любой другой ответ или сетевое исключение рассматривается как сбой. Полученные данные сервер отправляет по SMTP на адрес, заданный переменной окружения `FEEDBACK_RECIPIENT`, и параллельно дописывает в локальный лог-файл (см. README_backend.md).

Для локальной работы без внешних переменных можно использовать файл `config/smtp.env` (он читается автоматически и заполняет значения по умолчанию); при наличии переменных окружения они имеют приоритет. Если файл отсутствует, бэкенд использует встроенные дефолты для `smtp.crocomim.ru`, так что отправка писем не падает на чистом запуске.

### Фолбэк

Если отправка на `/feedback` невозможна, интерфейс предлагает mailto-ссылку на адрес `support@yourdomain.tld` с подготовленным текстом, включающим сообщение пользователя, контекст слова и данные клиента.

## Очередь и офлайн-сценарии

- Черновики сохраняются в `localStorage` под ключом `feedbackQueue`.
- Каждая запись содержит `id` (UUID), `createdAt`, исходные поля формы и статус `queued` / `sent`.
- Очередь дедуплицируется по `id` и сортируется по `createdAt`.
- При восстановлении сети (`window.ononline`) приложение пытается отправить все элементы очереди. После успешной синхронизации показывается toast «Отправили сохранённую обратную связь.»

## Расширение

- API `window.Feedback` предоставляет методы:
  - `open(context?)` — открыть форму, можно передать контекст вручную.
  - `setContextResolver(fn)` — зарегистрировать функцию, возвращающую контекст по умолчанию (используется горячей клавишей F).
  - `registerTrigger(element, resolver)` — привязать кнопку к форме с собственным контекстом.
  - `processQueue()` — принудительно запустить попытку синхронизации очереди.
- При необходимости можно подключить собственную аналитику: если глобальный объект `analytics.track` существует, форма отправляет события `feedback_open` и `feedback_submit`.

## Стилевые классы

Основные классы формы и уведомлений добавлены в `public/styles/main.css`. Ключевые блоки:

- `.feedback-modal` — контейнер модалки с ловушкой фокуса и закрытием по Esc.
- `.feedback-menu-btn` — кнопка в меню.
- `#qFeedbackBtn` / `#tFeedbackBtn` — кнопки в игровых режимах (используют базовый стиль `.btn ghost`).
- `.feedback-status` — блок статуса офлайн-отправки.
- `.toast-container` / `.toast` — система всплывающих уведомлений.

Для визуальных правок достаточно обновить Tailwind-совместимые классы в этих селекторах.
